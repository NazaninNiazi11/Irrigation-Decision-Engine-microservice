# Irrigation Decision Engine

A FastAPI microservice that analyzes soil and environmental data to calculate crop water stress and produce actionable irrigation recommendations. The service combines rule-based agronomic logic with live weather data and AI-generated explanations to help farmers decide *when*, *how much*, and *why* to irrigate.

---

## Features

- **Water-stress evaluation** — Combines soil moisture, temperature, humidity, and rainfall into a stress index (`low` / `moderate` / `high` / `critical`) and a recommended water volume in millimetres.
- **Live weather integration** — Pulls current conditions and 24-hour forecasts from the [Open-Meteo](https://open-meteo.com/) API based on each crop's registered latitude/longitude.
- **Growth-stage estimation** — Uses Growing Degree Days (GDD) to estimate the crop's current growth stage and adjusts water requirements accordingly.
- **AI-powered crop estimation** — When a user wants to register a crop that isn't in the predefined list, an LLM (via [OpenRouter](https://openrouter.ai/)) suggests reasonable moisture/temperature thresholds for review.
- **AI-generated explanations** — Each irrigation decision is paired with a farmer-friendly natural-language explanation generated by an LLM, with a deterministic rule-based fallback when no API key is configured.
- **JWT authentication** — All data endpoints require a bearer token issued by `/auth/login`.
- **Rate limiting** — Sensitive endpoints (AI estimation, decision evaluation, weather) are rate-limited via SlowAPI.
- **Seeded crop profiles** — A curated catalog of common crops is auto-loaded into the database on first startup.

| Layer            | Technology                                          |

## How to Run (Docker)

### Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) installed and running

### 1. Configure environment

Copy `.env.example` to `.env` and fill in values:

```bash
cp .env.example .env
```

| Variable             | Required | Description                                                                 |
|----------------------|----------|-----------------------------------------------------------------------------|
| `DATABASE_URL`       | yes      | Postgres connection string (the default points at the `db` compose service) |
| `POSTGRES_USER`      | yes      | Postgres role used by the `db` container                                    |
| `POSTGRES_PASSWORD`  | yes      | Postgres password                                                           |
| `POSTGRES_DB`        | yes      | Database name                                                               |
| `SECRET_KEY`         | yes      | JWT signing key — generate with `openssl rand -hex 32`. The app refuses to start with insecure defaults. |
| `OPENROUTER_API_KEY` | no       | Enables AI explanations and crop estimation. Leave blank to use the rule-based fallback. |
| `OPENROUTER_MODEL`   | no       | Override the default model (`anthropic/claude-haiku-4.5`)                   |

### 2. Start the project

```bash
docker compose up --build
```

This starts two containers:

| Container         | Description             | Port  |
|-------------------|-------------------------|-------|
| `irrigation-app`  | FastAPI application     | 8000  |
| `irrigation-db`   | PostgreSQL 15 database  | 5433  |

On first start the app creates tables and seeds the `crops` table from `app/data/crop_profiles.json`.

### 3. Verify it works

- Health check: <http://localhost:8000/health>
- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>

## Authentication

All endpoints (except `/health` and `/crop-profiles`) require a JWT Bearer token. Register a user, log in to get a token, then include it in requests.

### Auth Endpoints
| Method | Endpoint          | Description                              |
|--------|-------------------|------------------------------------------|
| POST   | `/auth/register`  | Create account (`username`, `password`)  |
| POST   | `/auth/login`     | Get JWT token (form-urlencoded)          |

### Using the token

```bash
# Register
curl -X POST http://localhost:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "pass123"}'

# Login
curl -X POST http://localhost:8000/auth/login \
  -d "username=admin&password=pass123"

# Use token on protected endpoints
curl http://localhost:8000/crops \
  -H "Authorization: Bearer <your_token>"
```

In Swagger UI (`/docs`), click the **Authorize** button and paste the token.

The frontend handles auth automatically — register and sign in, then use the app normally.

## API Endpoints

### Crops
| Method | Endpoint           | Description                                                |
|--------|--------------------|------------------------------------------------------------|
| GET    | `/crop-profiles`   | Public catalog of seeded crop profiles                     |
| POST   | `/crops/estimate`  | AI-suggested thresholds for an unknown crop (rate-limited) |
| POST   | `/crops`           | Register a new crop                                        |
| GET    | `/crops`           | List all crops                                             |
| GET    | `/crops/{crop_id}` | Get a specific crop                                        |

### Weather
| Method | Endpoint            | Description                                                       |
|--------|---------------------|-------------------------------------------------------------------|
| GET    | `/weather/current`  | Current weather + 24h forecast for a crop's location (Open-Meteo) |

### Sensor Data
| Method | Endpoint                   | Description                          |
|--------|----------------------------|--------------------------------------|
| POST   | `/sensor-data`             | Submit new sensor readings           |
| GET    | `/sensor-data`             | List sensor readings (filter by crop)|
| GET    | `/sensor-data/{sensor_id}` | Get specific sensor reading          |

### Irrigation Decisions
| Method | Endpoint                              | Description                                       |
|--------|---------------------------------------|---------------------------------------------------|
| POST   | `/decisions/evaluate/{sensor_data_id}`| Analyze readings and generate a decision          |
| GET    | `/decisions`                          | List decisions (filter by crop)                   |
| PATCH  | `/decisions/{decision_id}`            | Update status (e.g. *approved*, *completed*, *skipped*) |

### Decision Levels

The engine maps a computed *water-stress index* (0–1) to an action:

| Stress index | Level    | Action                                          |
|--------------|----------|-------------------------------------------------|
| `≥ 0.7`      | critical | Irrigate immediately                            |
| `0.5 – 0.7`  | high     | Irrigate within 2 hours                         |
| `0.3 – 0.5`  | moderate | Irrigate within 6 hours                         |
| `< 0.3`      | low      | No irrigation needed                            |

## Database Schema

The application uses four main tables:

- **users** — Registered users with bcrypt-hashed passwords
- **crops** — Crop name, species, moisture/temperature thresholds, optional latitude/longitude, water requirement, planting date
- **sensor_data** — Soil moisture, temperature, humidity, and rainfall readings tied to a crop
- **irrigation_decisions** — Decisions linked to a sensor reading: stress level, water-stress index, recommended water volume, status, and an explanation

## Frontend Interface

A minimal HTML frontend is included in the `frontend/` directory.

The interface allows users to:

- Register and sign in
- Browse seeded crop profiles or create a custom crop (optionally via AI estimation)
- Submit sensor data for a crop (with autofill from live weather)
- Evaluate irrigation decisions based on sensor readings and review the AI explanation

### How to Use

1. Start the backend service:

   ```bash
   docker compose up --build
   ```

2. Open the frontend in a browser:

   ```
   frontend/index.html
   ```

3. Use the interface in this order:

   - Register an account and sign in
   - Create a crop (or pick one from the seeded profiles)
   - Submit sensor data
   - Enter the returned sensor ID
   - Click **Evaluate Decision**

The frontend communicates with the FastAPI microservice via REST.
